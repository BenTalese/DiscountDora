Troubleshooting
Symptom	Fix
"Port 5170 already in use" on API start	Kill the process holding it, or edit config/dapi.appsettings.json and change API_PORT. CORS allowlist also needs updating in dora_api/startup.py if you change the web port.
Login page loops back to itself after submitting	Open browser devtools → Network tab. If /api/auth/login is failing with a CORS error, your Quasar dev server is on a port other than 5174 (Vite picked the next free one). Stop both servers, free port 5174, restart Quasar.
Browser shows "CORS preflight" failure	Same as above — the WEB_APP_PORT in config/dapi.appsettings.json must match the actual Quasar port.
API logs "PersistenceError: …has fields not mapped"	Out-of-sync code & DB. Try flask --app dora_api.app db upgrade. If that doesn't help, blow away data/dora.data.db and restart.
Migrations fail with "constraint not found"	An older copy of the FK-cascade migration is in your tree. Pull the latest 3a2c8f1d7b4e — the constraint-rename blocks were removed.
"Cannot find module 'pages/LoginPage.vue'" or similar	cd web_app && npx quasar dev --clean or delete web_app/.quasar and restart.
You forgot what user you registered as	del data\dora.data.db (PowerShell) / rm data/dora.data.db, restart API. Migrations re-run, you start fresh.

Distinctive elements
Hero band with the mascot, a time-aware greeting, and a single "right now" line that surfaces the most important state (e.g. "3 items are out of stock", "Tomorrow: Pasta Night for 2", or "Everything's stocked, planned, and quietly humming along" when there's no signal worth raising). The line follows a priority hierarchy: outages → next meal → low stock → empty book → all-clear.
Stock donut — an SVG ring sized at the card, segmented into in-stock / low / out. The centre label shows the total + "items". Segments animate in with a staggered delay; the legend sits beside it with colour dots, counts, and lowercase labels for readability. Has a real aria-label for screen readers.
Week-ahead strip — seven day tiles for today + the next six. Today is inverted (dark on cream). Days with meals tint warmly. Pips show how many entries; >2 collapses to +N. Each tile shows day-of-week and date number for unambiguous scanning.
Dora-says tip — a small floating chip bottom-right, dismissible. Pool of static tips, picked deterministically per calendar day so the same one shows all day but rotates tomorrow.
UX choices that aren't gimmicks
Warm palette scoped to the dashboard via CSS custom properties — doesn't leak into the rest of the app. Cream backgrounds (#fdfaf3 → #f4ecdc), warm yellow accent (#f4b740), food-friendly OK/warn/bad colours.
Every clickable card has a visible View → affordance in the top-right of its header — colour-shifts on hover. Cards without an action don't get one (Shopping Lists has no dedicated page yet, so it's intentionally non-clickable rather than fake-navigable).
Numbers are big and tight (letter-spacing: -0.02em, 700 weight) so they read as data, with lowercase muted labels underneath so the labels recede.
@media (prefers-reduced-motion) disables every transition for users who've opted out — common UX miss.
Mobile breakpoint stacks the hero buttons below the greeting instead of letting them shove the avatar off-screen.
Empty states have personality ("Nothing planned. Set up a week →") instead of just being blank.
Per-user card visibility still persists to localStorage, keyed by user_id so signing in as someone else on the same browser doesn't inherit your layout.
